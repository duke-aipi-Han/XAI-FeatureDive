# Phase 4 acceptance evidence

These files document implementation acceptance on real `phase1-v1` CPU model
responses. The demonstrations use curated **training** drawings from `demo-v1`,
chosen during Phase 2. They are not Phase 5 held-out evaluation results.

- `browser-tests.json`: ten Chrome acceptance tests, including the six existing
  explorer regressions; generated by `npm --prefix frontend run test:e2e`.
- `evidence-acceptance-record.json`, `hidden-acceptance-record.json`, and
  `shortcut-acceptance-record.json`: complete JSON downloads from successful
  guided flows. Hypotheses/reflections are explicitly authored automated test
  examples, **not student responses or evidence of learning gains**. Model
  predictions, arrays, interventions, and provenance are actual API outputs.
- `demo-results.md` and `demo-summary.json`: tables/metadata derived from those
  records by `uv run --locked python -m experiments.phase4_report`. Record
  SHA-256 values are recorded in the summary. The script checks checkpoint,
  model version, and training partition against the registry.
- `evidence-comparison.png`, `hidden-comparison.png`, `shortcut-reveal.png`, and
  `mobile-challenge.png`: actual guided-flow screenshots. `conv2-ablation.png`,
  `mobile-input.png`, and `gate-experiment.json` are the rerun explorer regression
  evidence. Original Phase 3 artifacts remain under `results/phase3/`.

A/B assignment, timestamps, experiment IDs, and test timing vary on each run.
Feedback and comparison numbers always derive from measured outputs. Gray is
optional and excluded from the three-training-color sensitivity calculation.

See [the teacher guide and report](../../docs/phase4-challenges.md) for the
reproducible UI path, thresholds, student explanations, and limitations.
